# environment_sensitive_variables (Ephemeral Resource)

Reads secrets, such as tokens or passwords, from the environment of the Terraform process. Same as `environment_variables`, except that the provider schema marks `items` as sensitive. Terraform reads them again in every plan and apply, and never stores them in plan or state files. Requires Terraform 1.10 or later.

Use the variables in contexts that accept ephemeral values, such as provider
configuration blocks, write-only arguments of managed resources (Terraform 1.11
or later), locals, and other ephemeral resources.

Terraform reads the variables again when it applies a saved plan, so their values
can differ between plan and apply, for example when plan and apply run in
different CI/CD jobs.

~> **Note:** Terraform doesn't currently apply the sensitivity of ephemeral
resource attributes to the values that you reference, so `issensitive()` returns
`false` for them. The values are still protected because they're ephemeral:
Terraform never stores them in plan or state files, and doesn't display them in
diagnostics or provisioner output. Wrap a value with `sensitive()` if it must
also be marked as sensitive.

-> **Note:** The provider reads the environment of the Terraform process. With
remote execution, such as HCP Terraform remote runs, this is the environment of
the remote worker.

Referencing a variable that isn't set, as in `items["NAME"]`, is an error. Use
`lookup()` with a default value for optional variables.

## Example Usage

```terraform
terraform {
  # Write-only arguments require Terraform 1.11 or later.
  required_version = ">= 1.11"
}

# Reads the database password from the DB_PASSWORD environment variable.
ephemeral "environment_sensitive_variables" "database" {
  filter = "^DB_PASSWORD$"
}

resource "aws_db_instance" "example" {
  identifier          = "example"
  engine              = "postgres"
  instance_class      = "db.t4g.micro"
  allocated_storage   = 20
  username            = "app"
  skip_final_snapshot = true

  # Write-only arguments accept ephemeral values, and Terraform never stores them.
  password_wo = ephemeral.environment_sensitive_variables.database.items["DB_PASSWORD"]
  # Terraform can't detect changes to write-only arguments: increment the
  # version to update the password.
  password_wo_version = 1
}
```

## Schema

### Optional

- `filter` (String) Regular expression, in [RE2 syntax](https://github.com/google/re2/wiki/Syntax), matched against the name of each environment variable. Only matching variables are returned. The match is not anchored: use `^NAME$` to match a single variable. When omitted, every environment variable is returned.

### Read-Only

- `items` (Map of String, Sensitive) Matching environment variables, keyed by name.
